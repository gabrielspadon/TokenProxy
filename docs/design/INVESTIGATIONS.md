# Persistent investigations contract

The existing workspace gains saved investigations, named filter sets and exact-record bookmarks. All entries belong to the installation's authenticated operator scope, not private individual-user accounts. The server fixes `ownerScope` to `installation-operator`; clients cannot supply or change it.

## Saved definitions

`GET /api/admin/investigations` returns `{items, ownerScope, limit:200}`. Each entry contains `{id,name,kind,definition,version,ownerScope,createdAt,updatedAt}`. The installation permits at most 200 entries, so the list is complete rather than silently paginated.

`POST /api/admin/investigations` accepts `{name,kind,definition}`. `PUT /api/admin/investigations/[id]` additionally requires the last observed integer `version`. `DELETE` requires `{version}`. Conflicts return 409 `version_conflict`, missing records 404, malformed bodies 400, bodies over 32 KiB 413, and unavailable persistence 503. Authentication precedes reading or writing state; mutations retain the existing verified-loopback requirement. The existing SQLite adapter transaction makes version checks atomic.

Names are plain strings of at most 80 characters. Definition schemas 1 and 2 permit only a lens, fixed UTC scope, typed selected identity, up to 100 distinct comparison account IDs, Context page/client/project controls and Economics cohort/grouping/status/sort controls. Unknown keys, control characters and invalid IDs/options/dates are rejected. No raw row payloads, prompts, responses, credentials or session hashes are accepted. Filter sets restore scope while retaining current selected evidence. Other entry kinds restore their exact saved selection and comparison state. Restoring never substitutes another record when the original is missing or excluded.

Schema 2 additionally permits `context.baseline={id,sessionId}`. Only the exact identity is saved; structural payloads and cached measurements are excluded. Version 1 remains readable and restores without a baseline. Baseline identity survives lens and scope changes; restoration reads its current retained evidence and clearly reports unavailable or expired identities. Named filter sets do not replace the retained baseline.

Typed selections are `account`, `context-session`, `context-attempt`, `economics-record`, `economics-group`, or `routing-switch`. Context selections require the exact numeric session ID. Ledger selections use numeric completion `recordId`, separately from server request IDs. Group identities encode grouping and provider/model/account dimensions. Optional identity metadata supplies scope-exclusion feedback; it is not evidence of a source link.

## Evidence export

`POST /api/admin/investigations/export` accepts `{mode:'selected'|'population'|'comparison'|'attempt-comparison',definition}` and executes a named read-only operation on the existing bounded analytics worker. Every export uses one SQLite read transaction and returns `{manifest,items,freshness}`. The manifest records the authenticated installation operator scope, source, exact definition, applied time bounds, returned/total count, missing identity coverage, units, omitted fields, completeness and declared limits. When downloaded through a private preview, the browser adds the observed isolation kind and original capture timestamp, separately from worker freshness. Source links are never inferred from timestamp or token similarity.

Exact selected record exports ignore shared filters deliberately; this is stated before export and in the manifest. Selected Economics cohorts retain the fixed shared time and dimension scope, and conflicting dimensions are refused. Comparison exports read only the requested accounts and disclose missing/deleted members. Complete population exports apply shared filters and relevant lens controls across all matching records, independent of the visible page. Capacity offers exact accounts/comparisons; time-filtered populations belong to Economics, Context or routing.

Context `attempt-comparison` requires a selected Context attempt and a distinct baseline ID. It reads exactly both request/session tuples, independent of shared filters and account comparisons, and attaches their exact owned events, structural boundaries, stages and linked cost records. `requestedAttempts`, `missingAttempts` and `comparisonComplete` distinguish a fully read retained population from an incomplete requested pair. An absent or mismatched tuple is never replaced by another request. Both attempts are re-read together in the export transaction; the file does not claim to reproduce an older inspector read.

The initial synchronous download limit is 5000 primary records and 8 MiB. The final API UTF-8 response includes the worker freshness envelope in this limit. The browser checks again after adding preview metadata and JSON indentation; it creates no download URL when the complete file would exceed the same cap. Nothing is truncated. A larger server result returns 413 and no partial file, with a request to narrow the scope. Context stage rows remain attached to their exact request IDs. Private identities, credentials, bodies and freeform error/reason payloads are excluded. Historical pending receipts are not live work; application model-rate estimates are not subscription bills.

`GET /api/analytics?view=economics&recordId=<numeric>` is the additive exact legacy-ledger lookup. Existing `requestId`, `logicalRequestId`, `sessionId` and `projectId` filters keep their established meanings. Numeric completion IDs must never be substituted for request attribution.

Context exports currently include attempt fields and ordered shaping stages. The newly introduced structure snapshots and explicit client-event collections are excluded and declared in coverage; their associated-evidence export remains a separate integration task.

`GET /api/admin/receipts` accepts `provider`, `connectionId`, `model`, inclusive `since`, exclusive `until`, `limit` and opaque cursor. SQL applies every predicate to the complete retained log before keyset paging, ordered by UTC timestamp and ID. Provider refers to the destination account's current configured provider, not reconstructed historical provider membership. Deleted destination accounts have unknown provider. Exact receipt lookup also queries the full log. Routing controls and saved investigations use the shared workspace scope.

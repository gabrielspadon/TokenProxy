# Everyday workspace correction

This correction supersedes the field-exposure decisions in COMPACT-WORKSPACE-20260907.md. The accepted light Manrope and petrol workspace remains. Compact means fewer simultaneous decisions, coordinated controls and readable data, rather than smaller text or more nested panels.

## Interaction contract

The navigation starts with daily work. A single visible Everyday / Advanced choice exposes specialist destinations without removing search, direct links, permissions or saved state. The current destination remains visible when the operator changes navigation scope. The preference is local presentation state and never changes routing or enables transformations.

Capacity begins with recorded requests and cache activity followed by account cards. Historical activity and current quota observations carry separate units and timestamps. Requests with explicit identities remain distinct from physical attempts; cache token share is never called a request hit rate. Sparse buckets and missing observations are not filled with invented availability. The chart and its keyboard-accessible data view share the same scope.

Account cards keep all quota windows, reset times, pause/resume and auto-pause limits in place. An Everyday / Advanced selection applies to the whole account panel, with priority and specialist evidence in Advanced. Search, status, sorting, comparison and visibility retain their state. Saving still compares a captured baseline and verifies refreshed state. Switching presentation does not discard edits.

Token savings begins with understandable control groups and saved on/off state. Specialist thresholds and configuration share an Advanced view rather than appearing on every initial card. Every supported transformation remains independently configurable. Content-changing processing retains explicit consent, known-current configuration and verified results. No preset silently changes saved policy.

Remote is retired from current source, APIs, bootstrap, CLI, navigation, documentation, fixtures and tests. Operator-managed networking and outbound proxy paths remain independent capabilities. Existing saved database fields are retained inertly for data preservation and excluded from the current settings contract. The standalone Translation workbench and its dedicated APIs are retired; gateway request/response format conversion continues to support clients and providers. The application remains English only.

## Execution and ownership

1. Remote implementation lane removes its exclusive sources and runtime wiring, then verifies authentication and settings preservation.
2. Translation lane removes its exclusive workbench and unused log-capture service, and reconciles current documentation and English-only evidence tooling.
3. Capacity lane implements the activity band and simpler account surface, preserving draft and selection contracts.
4. Root owns shared navigation, icon semantics and the remaining everyday controls. One owner manages build output and preview processes.
5. Fixture lane removes retired route expectations while preserving process, network and secret guards. All operational browser mutations run against credentialless disposable fixtures.
